Bank Account Linking

A complete explanation of what "linking a real bank account" means, how it works in the industry, what Budgetix currently does, and the roadmap to full Open Banking integration.

1. Two Ways to Track a Bank Account in a Finance App

Every personal finance application must choose between two fundamental approaches: manual tracking and live bank linking. They are not mutually exclusive — most mature apps offer both.

📝 Manual Tracking

The user tells the app about their accounts and types in (or imports) their own transactions. The app never contacts the bank.

No bank credentials needed Works with any bank worldwide Full privacy Requires manual data entry Balance can drift out of sync

🔗 Live Bank Linking (Open Banking)

The app connects to the bank through a regulated API (like Plaid or Tink). Transactions and balances sync automatically.

2. What Budgetix Does Today

Budgetix uses the manual tracking model. When you create an account you give it a name, type, starting balance, currency, and optionally your institution name and last 4 digits of the account number. The app stores everything in its own PostgreSQL database — it never contacts your bank.

Note: "Institution Name" and "Last 4 Digits" are purely informational labels — they help you identify which real-world account a Budgetix account represents. No data is sent to any bank and no bank credentials are stored.

When you add a real transaction (salary deposited, grocery purchase), you create it manually in Budgetix. The app adjusts the account balance automatically and you can import transactions in bulk via CSV.

3. How Real Bank Linking Actually Works

Real bank linking uses an Open Banking API provider (aggregator) that sits between your app and thousands of banks. The most widely used providers are Plaid (US/CA), Tink (EU), Basiq (AU), and TrueLayer (UK/EU).

The full user flow — step by step

1
User clicks "Link Bank"
App requests a short-lived link_token from the provider API (server-side)
→
2
Provider Popup / Redirect
Plaid Link / Tink widget opens in an iframe or redirect. User picks their bank.
→
3
User Authenticates at Bank
Enters bank credentials directly in the provider widget — your app never sees them.
→
4
OAuth Consent
User grants read-only consent: balances, transactions (typically 90 days back).
→
5
Access Token Issued
Provider sends a permanent access_token to your backend via callback/webhook.
→
6
Data Sync
App polls or receives webhooks: balances updated, new transactions imported automatically.

4. Technical Architecture for Budgetix + Plaid

Here is how the backend and frontend would be wired for a full Plaid integration inside Budgetix's Spring Boot + Angular architecture.

🖥️ Backend (Spring Boot)

// New entities needed
PlaidItem           // one per linked bank
  - itemId          // Plaid item ID
  - accessToken     // encrypted, never exposed
  - institutionId
  - userId

PlaidAccount        // one per bank sub-account
  - plaidAccountId
  - budgetixAccountId  // FK → accounts
  - lastSyncedAt

// New endpoints
POST /plaid/link-token   // create Plaid link token
POST /plaid/exchange     // exchange public_token → access_token
POST /plaid/webhook      // receive balance/tx updates
POST /plaid/sync/{id}   // manual re-sync trigger
DELETE /plaid/{id}      // unlink (revoke access)

🌐 Frontend (Angular)

// Plaid Link widget (npm package)
"ngx-plaid-link"
// or vanilla Plaid Link JS loaded lazily

// Flow in AccountsComponent
linkBank() {
  // 1. fetch link_token from backend
  plaidService.getLinkToken()
    .subscribe(token => {
      // 2. open Plaid widget
      openPlaidLink(token, {
        onSuccess: (publicToken) => {
          // 3. exchange token
          plaidService.exchange(publicToken)
            .subscribe(() => this.load());
        }
      });
    });
}

Data flow — Webhook-driven sync

// Plaid sends this webhook when new transactions are available:
{
  "webhook_type":  "TRANSACTIONS",
  "webhook_code":  "SYNC_UPDATES_AVAILABLE",
  "item_id":       "abc123"
}

// Your Spring Boot webhook handler:
@PostMapping("/plaid/webhook")
public void handleWebhook(@RequestBody PlaidWebhook event) {
    if ("SYNC_UPDATES_AVAILABLE".equals(event.webhookCode())) {
        PlaidItem item = plaidItemRepository.findByItemId(event.itemId());
        // pull latest transactions via Plaid SDK
        List<Transaction> newTxs = plaidClient.transactionsSync(item.getAccessToken());
        // save to transactions table (skip duplicates by plaidTransactionId)
        transactionSyncService.upsert(item.getUserId(), newTxs);
        // update account balance
        plaidClient.accountsBalanceGet(item.getAccessToken())
            .forEach(this::updateAccountBalance);
    }
}

5. API Providers — Who to Use

Choosing the right aggregator depends on your target market (country coverage) and budget.

🇺🇸 Plaid
US · CA · UK · EU
12,000+ banks Best developer docs

De-facto standard in the US. Free sandbox. Production: ~$0.30/connected account/month.

🇪🇺 Tink (Visa)
EU · UK · Nordic
PSD2 compliant 3,400+ banks

Best for European apps. Acquired by Visa in 2021. Strong regulatory compliance out of the box.

🇬🇧 TrueLayer
UK · EU · AU

UK Open Banking specialist. Also supports payment initiation (not just read), so users can pay bills in-app.

🇦🇺 Basiq

Australian Consumer Data Right (CDR) compliant. Strong coverage for AU/NZ banks including the Big 4.

Free for basic account data in EU. Acquired by GoCardless. Good for budget-conscious projects.

6. Security Considerations

🔐 What you NEVER store

✗Bank username/password
✗Full account number
✗PIN or security answers
✗Card CVV

🛡️ What you must secure carefully

✓access_token → encrypt at rest (AES-256)
✓Webhook endpoint → verify Plaid signature header
✓HTTPS only for all API calls
✓Revoke token on account disconnect
Regulatory note: In the EU, accessing bank data via PSD2 requires your app to be registered as an AISP (Account Information Service Provider) with your national regulator, OR you must route all requests through a licensed aggregator like Tink/TrueLayer. Using a licensed aggregator handles this for you.

7. Budgetix Integration Roadmap

Here is the phased plan from the current manual-tracking state to a fully live-linked bank integration.

Phase 1 — Done ✓
Manual account management + bank details
Users create accounts manually. Institution name and last 4 digits are optional informational fields that make accounts identifiable without any bank connection. CSV import for bulk transaction loading.
Phase 2 — Next
Plaid / Tink Sandbox Integration
Add PlaidItem and PlaidAccount entities. Implement link-token → exchange → access-token flow in a Spring Boot service. Use Plaid sandbox to auto-import fake transactions. No real bank data yet.
Phase 3
Webhook-driven live sync
Implement the POST /plaid/webhook handler. When Plaid fires SYNC_UPDATES_AVAILABLE, fetch new transactions and update balances. Store plaidTransactionId on each transaction to prevent duplicates.
Phase 4
Account reconciliation UI
Show a "Last synced X minutes ago" badge on linked accounts. Add a manual Re-Sync button. Flag transactions that were auto-imported vs manually entered. Let users review and categorize auto-imported transactions.
Phase 5 — Future
Multi-region support (Tink for EU, Basiq for AU)
Add a region selector at account-link time. Route EU users to Tink/Nordigen, US users to Plaid, AU users to Basiq. Abstract behind a common BankSyncProvider interface in the backend so switching providers requires minimal changes.

8. Summary — The Short Answer

A "real bank account" in Budgetix right now means: you create an account record, set the starting balance manually to match your actual bank balance, and then log every income/expense transaction yourself (or import via CSV). The "Institution Name" and "Last 4 Digits" fields let you label the account so it's clear which real-world bank account it represents — but no data flows between Budgetix and your bank.


Full bank linking (like Mint, YNAB, or Copilot) means: you click "Connect Bank", go through a secure OAuth flow with your bank, and from that point on your transactions and balance sync automatically — usually within 24 hours of them posting at your bank. This requires integrating with a third-party aggregator (Plaid, Tink, etc.), passing regulatory checks, and paying per-user API fees.


Budgetix is architected to support full linking in a future phase. The account data model, transaction schema, and service layer are already designed to accommodate it.
